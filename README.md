# MCU Council RSVP (ระบบตอบรับเข้าร่วมประชุมสภามหาวิทยาลัย)

**สำนักงานสภามหาวิทยาลัย มหาวิทยาลัยมหาจุฬาลงกรณราชวิทยาลัย (มจร.)**

---

## 🏛️ เกี่ยวกับระบบ

**MCU Council RSVP** เป็นระบบ Web Application แบบ Full-stack ที่พัฒนาขึ้นเพื่ออำนวยความสะดวกให้สำนักงานสภามหาวิทยาลัย มจร. ในการสร้าง บริหารจัดการ และติดตามการตอบรับเข้าร่วมประชุมของกรรมการสภาฯ และผู้ได้รับเชิญ โดยรองรับรูปแบบการประชุมทั้ง **Onsite, Online และ Hybrid** รวมถึงการแจ้งลา การแจ้งไม่สามารถเข้าร่วม และการมอบหมายผู้แทน พร้อมทั้งระบบเช็กชื่อวันประชุม การคำนวณและรับรององค์ประชุมอัตโนมัติตามระเบียบสภาฯ และการออกรายงานทางการ 10 รูปแบบ

## 🌟 จุดเด่นและคุณสมบัติสำคัญ

1. **รองรับปฏิทินไทยและปี พ.ศ. (Thai Buddhist Era)**
   - จัดเก็บข้อมูลวันและเวลาตามมาตรฐานสากล ISO 8601 ในฐานข้อมูล
   - เลเยอร์การแสดงผลและแบบฟอร์มแปลงเป็นภาษาไทยและปี พ.ศ. (เช่น "๒๔ กันยายน ๒๕๖๙") อย่างถูกต้องตามแบบแผนสารบรรณ
2. **ระบบสลับบทบาทด่วน (Quick Role Switcher & RBAC)**
   - รองรับ 6 บทบาทตามข้อกำหนด: `super_admin`, `staff`, `secretary`, `chairperson`, `member`, `delegate`
   - มีเมนูลอยสำหรับสลับบทบาทเพื่อการทดสอบได้ทันทีในคลิกเดียว
3. **การสร้างการประชุมแบบ Step Wizard (3 ขั้นตอน พร้อม Live Preview)**
   - **ขั้นตอนที่ 1**: คณะกรรมการ, ครั้งที่ (เช่น 8/2569), ปี พ.ศ., ประเภทวาระ
   - **ขั้นตอนที่ 2**: วัน เวลา, กำหนดปิดรับตอบรับ (มีระบบ Validation บังคับให้วันปิดรับต้องอยู่ก่อนวันประชุม), รูปแบบ Onsite/Online/Hybrid, กำหนดสถานที่เริ่มต้นอัตโนมัติเป็น *"ห้องประชุม 401 ชั้น 4 อาคารพระธรรมวชิรคุณาธาร (โกศล มหาวีโร) อาคารสำนักงานอธิการบดี มจร. วังน้อย"* และแก้ไขได้เสมอ
   - **ขั้นตอนที่ 3**: เลือกสมาชิก, เพิ่มบุคคลภายนอก, แนบหนังสือเชิญ/ระเบียบวาระ, เทมเพลตแจ้งเตือน
   - **Live Preview**: แสดงข้อความประกาศทางการแบบเรียลไทม์ขณะกรอก
4. **หน้าตอบรับเฉพาะบุคคล (Tokenized Personal RSVP)**
   - กรรมการเข้าถึงผ่านลิงก์เฉพาะบุคคล หรือหน้า "การประชุมของฉัน"
   - ข้อมูลชื่อ-ตำแหน่ง Prefilled อนุญาตให้แก้ไขเฉพาะเบอร์โทรศัพท์และอีเมล
   - Radio Cards 4 ทางเลือก: เข้าร่วม (Onsite/Online), ไม่เข้าร่วม, ลาประชุม, มอบหมายผู้แทน
   - ระบบแนบหนังสือมอบหมายและหนังสือขอลา
   - หน้าผลตอบรับพร้อม **QR Code และ Reference Code** สำหรับสแกนเข้าห้องประชุม
   - ข้อความปฏิบัติตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA)
5. **ระบบตรวจสอบคำขอผู้แทนและคำขอลา (Secretary Review)**
   - แท็บแยก: ผู้แทน, คำขอลา, ไม่สามารถเข้าร่วม
   - ตรวจดูเอกสารแนบและเหตุผล
   - ปุ่ม อนุมัติ / ไม่อนุมัติ / ขอข้อมูลเพิ่มเติม (บังคับกรอกหมายเหตุเมื่อไม่อนุมัติหรือขอข้อมูลเพิ่ม)
   - **การควบคุมสิทธิ์องค์ประชุมของผู้แทน**: ระบบกำหนดให้ผู้แทนไม่ถูกนับเป็นองค์ประชุมอัตโนมัติ เว้นแต่เลขานุการสภาฯ กำหนดสิทธิ์อนุมัติ
6. **ระบบเช็กชื่อวันประชุมและคำนวณองค์ประชุม (Quorum Engine)**
   - แสดงสถานะ **"ครบองค์ประชุม"** หรือ **"ยังไม่ครบองค์ประชุม"** ชัดเจนแบบเรียลไทม์
   - ตั้งค่าเกณฑ์: มากกว่ากึ่งหนึ่ง (>1/2), ไม่น้อยกว่ากึ่งหนึ่ง (>=1/2), หรือกำหนดจำนวนขั้นต่ำ
   - ตรวจสอบเงื่อนไขต้องมีนายกสภาฯ หรือผู้แทนประธานเข้าร่วม
   - เช็กชื่อได้ 3 วิธี: สแกน QR Code หน้าห้องประชุม, เจ้าหน้าที่เช็กชื่อแทน, ลิงก์ออนไลน์
   - บันทึกเวลาเข้า-ออก และหมายเหตุ (เช่น มาสาย, ออกก่อน)
   - ปุ่ม **"รับรององค์ประชุม"** สำหรับเลขานุการสภาฯ พร้อมบันทึก Quorum Log
7. **ระบบรายงานและสถิติ (Reports & Analytics 10 รูปแบบ)**
   - สรุปผลตอบรับ, ผู้เข้าร่วม Onsite, ผู้เข้าร่วม Online, รายชื่อผู้ลา, ผู้แทน, ผู้ยังไม่ตอบ, เช็กชื่อจริง, สถานะองค์ประชุม, สถิติรายบุคคล และสถิติรอบปี
   - หน้าจอ **Interactive Preview** ก่อนดาวน์โหลด
   - ส่งออกเป็นไฟล์ **Excel (.xlsx)** และพิมพ์ออกทางกระดาษ / **PDF** ได้ทันที
8. **ฐานข้อมูลกรรมการและนำเข้า Excel (Member Directory)**
   - ฐานข้อมูลสมาชิกสภาฯ พร้อมสิทธิ์องค์ประชุมและสิทธิ์ออกเสียง
   - แจ้งเตือนสถานะใกล้ครบวาระ (< 60 วัน)
   - นำเข้าข้อมูลผ่าน Excel พร้อมหน้า **Preview Modal** ตรวจสอบก่อนยืนยันบันทึก

## 🛠️ เทคโนโลยีที่ใช้ (Tech Stack)

- **Frontend**: React 18 + TypeScript + Vite
- **Styling**: Tailwind CSS + MCU Theme Colors (ม่วงทองประจำสถาบัน)
- **Icons**: Lucide Icons (`lucide-react`)
- **Routing**: React Router DOM v6
- **Forms & Validation**: Zod + React Hook Form
- **Data & Storage**: Dual-mode Architecture (Reactive LocalStore พร้อม LocalStorage Persistence + Supabase Adapter)
- **Charts**: Recharts
- **QR Code**: `qrcode.react`
- **Spreadsheet & PDF**: SheetJS (`xlsx`) + Print CSS Stylesheet


## 🔑 การทดสอบระบบตามบทบาท (Role-Based Testing)

ในทุกหน้าจอจะมีปุ่ม **"บทบาท: [Role]"** ที่มุมขวาบนของ Navbar ซึ่งสามารถคลิกเพื่อสลับมุมมองได้ทันที:

| บทบาท | ชื่อบัญชีตัวอย่าง | ขอบเขตการใช้งาน |
|---|---|---|
| **super_admin** | นายสมศักดิ์ พิทักษ์ธรรม | จัดการผู้ใช้ สิทธิ์ การตั้งค่าระบบ และ Audit Log |
| **staff** | น.ส.วราภรณ์ กัลยาณมิตร | สร้างการประชุม ส่งคำเชิญ ติดตามคำตอบ เช็กชื่อวันประชุม |
| **secretary** | พระมหาบุญรอด ปิยธมฺโม, รศ.ดร. | ตรวจสอบคำขอลา/ผู้แทน รับรององค์ประชุม ออกรายงาน |
| **chairperson** | พระธรรมวชิรญาณคุณ (สมบุญ) | ดูสรุปผลการประชุมและรายชื่อ |
| **member** | พระพรหมบัณฑิต / ศ.ดร.วิริยะ | ตอบรับการประชุม ขอลา มอบหมายผู้แทน แก้ไขข้อมูลติดต่อ |
| **delegate** | ผศ.ดร.อภิชาต สิริปัญโญ | ดูข้อมูลการประชุมที่ได้รับมอบหมาย |

## 🗄️ โครงสร้างฐานข้อมูล (Supabase / PostgreSQL)

ไฟล์ `supabase/schema.sql` ประกอบด้วย 17 ตารางหลัก:
1. `profiles`: บัญชีผู้ใช้งานและข้อมูลติดต่อ
2. `roles`: สิทธิ์และคำอธิบายบทบาท
3. `committees`: ข้อมูลคณะกรรมการ (สภาฯ, ก.บ.ม., อนุกรรมการ)
4. `committee_members`: สมาชิกสภาฯ วาระดำรงตำแหน่ง และสิทธิ์องค์ประชุม
5. `meetings`: รายการประชุม วัน เวลา รูปแบบ สถานะ และสถานที่
6. `meeting_documents`: เอกสารแนบ (หนังสือเชิญ, ระเบียบวาระ)
7. `meeting_invitees`: รายชื่อผู้ได้รับเชิญและ Token ลิงก์เฉพาะบุคคล
8. `rsvp_responses`: คำตอบการเข้าร่วม (Onsite/Online/อาหาร)
9. `delegate_requests`: คำขอมอบหมายผู้แทนและหนังสือมอบหมาย
10. `leave_requests`: คำขอลาและหนังสือลา
11. `attendance_logs`: บันทึกการเช็กชื่อจริง เวลาเข้า-ออก และวิธีการ
12. `quorum_rules`: เกณฑ์การคำนวณองค์ประชุมของการประชุม
13. `quorum_logs`: ประวัติการตรวจสอบและการรับรององค์ประชุมโดยเลขาฯ
14. `notifications`: รายการแจ้งเตือนภายในระบบ
15. `notification_logs`: บันทึกประวัติการส่งออก Email/LINE
16. `audit_logs`: บันทึกประวัติการแก้ไขและพิจารณาข้อมูล
17. `system_settings`: ค่าสถานที่ตั้งต้นและแม่แบบข้อความ
